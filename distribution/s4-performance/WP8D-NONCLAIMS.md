# S4-WP8D non-claims

WP8D admits only a symbolic x86-64 encoding contract and exact width equations
for the four sealed WP8C plans. It does not contain or admit candidate machine
bytes, an encoder implementation, an ELF image, native execution, a benchmark
rerun, a changed threshold, a speedup, or a public performance claim.

The fixed `r12` templates are not a general register allocator. A later gate
must implement and independently reconstruct candidate bytes before any native
correctness work can begin. The exact WP5D target remains the rollback artifact.
