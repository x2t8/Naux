# S4-WP5A non-claims

This work package does not claim:

- that the emitted request is a residual program or native artifact;
- that the existing VM or trace carrier occupies the `naux-residual` role;
- that work has been precomputed, reduced to an oracle, or replaced by a
  kernel-specific host implementation;
- that four standalone ELF64 artifacts replay successfully;
- any runtime, compile-time, throughput, latency, ratio, or C/C++ comparison;
- readiness to enter the controlled measurement boundary.

`request-status=admitted` means only that the exact static inputs, ordinary
frontend program identities, and dynamic-work obligations are sealed and can
be reproduced by independent untimed replay.
