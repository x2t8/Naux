# S4-WP7E — Performance claim admission boundary

WP7E freezes the boundary between a valid threshold candidate and a public
performance statement. It is deliberately blocked: local authorities,
synthetic fixtures, a passing WP7D report, or maintainer intent cannot alone
admit a claim.

```bash
python3 scripts/s4_claim_admission.py
```

The static report names four unresolved prerequisites. There is no bundle,
candidate, request, approval, or network mode. A later protocol revision may
add an admission path only after the exact WP5D–WP7D chain is tracked and
accepted by public CI and an eligible WP7C bundle exists.

The only permitted future statement class is a bounded observation qualified
by exact host, source commit, bundle root, and kernel outcomes. Language-wide
leadership, production performance, and unmeasured-workload extrapolation are
forbidden by this version.
